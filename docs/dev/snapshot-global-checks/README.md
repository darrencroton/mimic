# Snapshot-Global Modules Plan: Executable Contract Checks

**Purpose:** Reproducible, planning-only checks that the frozen plan [MIMIC-SNAPSHOT-GLOBAL-MODULES-PLAN.md](../MIMIC-SNAPSHOT-GLOBAL-MODULES-PLAN.md) survives the Project Manager (PM) tooling it will be executed under, that its C callback contract is enforceable by the type system where the plan says it is, and that its SHAM prescription is mathematically testable in the way its acceptance criteria demand. The evidence summary produced from a run lives in [MIMIC-SNAPSHOT-GLOBAL-MODULES-PLAN-CHECKS.md](../MIMIC-SNAPSHOT-GLOBAL-MODULES-PLAN-CHECKS.md).

These scripts are development-pathway artifacts under `docs/dev/`, not production code, not project tests, and not a source of facts for user documentation. A green run proves properties of the plan text, of the installed PM library, of the compiler against the current generated headers, and of the specified arithmetic. It proves nothing about a driver integration; none exists at the planning baseline and no mock here stands in for one. It is a pre-implementation checker: its drift check and its "plan-named new path is absent" checks are meant to fail once any slice lands, and a passing phrase check shows only that the named sentences survived, not that the contract has no other gaps.

## Running

```bash
python3 docs/dev/snapshot-global-checks/run_checks.py
```

Defaults assume the skills root at `/Users/dcroton/Documents/AI/skills` with PM under `project-manager/scripts`; override with `--skills-root`, `--pm-scripts` or the `MIMIC_SKILLS_ROOT` / `MIMIC_PM_SCRIPTS` environment variables. The C probes use `cc` (override with `--cc`) and the generated header already present in `src/include/generated/`; the runner never invokes `make`. Python 3.13 or newer is required because PM's surface matcher uses `PurePosixPath.full_match`. Only the standard library is used.

Each suite can also run alone and accepts `--json OUT` for a machine-readable report:

```bash
python3 docs/dev/snapshot-global-checks/check_plan_contract.py
python3 docs/dev/snapshot-global-checks/c_const_view_probes.py
python3 docs/dev/snapshot-global-checks/sham_rank_oracle.py
```

Outputs go to `results/` (gitignored). Every check emits one `MIMIC_RESULT:` marker line so counts come from markers, never prose, and every script exits nonzero on any FAIL or ERROR.

## What each suite checks

- `check_plan_contract.py` imports the installed `pm_lib` and runs the real `parse_plan`, `plan_check_report`, `eligibility`, `next_slice`, `render_developer_prompt`, `render_reviewer_prompt` (for `drift-audit` and `code-review`), `is_authorized_path` and `unauthorized_files`. It first checks drift from the planning baseline: HEAD must descend from the baseline commit, and every path that differs from it (committed since the baseline, staged, unstaged or untracked) must lie inside the planning surface, which is exactly the plan, the pathway, the two planning records and this directory; a planning-only commit therefore passes, any other change fails, and a missing or failing Git is an explicit error rather than a pass. The classifier is also exercised on synthetic path sets (runtime sources, other `docs/` files, other `docs/dev/` plans, look-alike directory names, generated files) without touching Git. It then verifies that all five receipts parse with every required section, that risk flags and eligibility behave as the plan's checkpoint prose says, that concrete witness paths per slice are authorized while known-unauthorized paths are rejected, that every acceptance checkbox, the recommended model/effort line and a list of critical contract phrases (`fixtures/critical_phrases.txt`) reach both seats verbatim, and that the plan's cited line anchors still hold at the working tree (`fixtures/anchors.json`). Finally it writes the corrupted variants defined in `plan_mutations.py` to temporary storage and checks that PM reports exactly the errors and warnings it should, and that the variants PM cannot see (a lost oracle, log-form, harness-key or `FLT_MAX` criterion, a bound moved after exponentiation, a weakened tolerance, a manual test renamed into the auto-discovered tier, a swapped model/effort, a blanked audit flag) are caught by the compensating guards implemented here.
- `c_const_view_probes.py` compiles disposable translation units against the real `module_interface.h`, `types.h` and generated `property_defs.h` with `-fsyntax-only -Werror -Wcast-qual`. Positive probes (galaxy write through the const view, zero count with a null population, private scratch sort, int64 indexing) must compile; negative probes (halo field write, pointer swap, reorder, `qsort`/`memcpy` on the borrowed view, context write, `module_emit_event` with the snapshot context, handing the const view to the FoF signature, casting const away) must fail. Two probes are labelled limitations: retaining the borrowed pointer and using `CentralHalo` as a snapshot offset both compile, so those rules need tests, not types.
- `sham_rank_oracle.py` implements the Slice 3 prescription in pure Python in its frozen expanded logarithmic form with the log-space upper bound, checks it against an exact rational oracle (`Fraction`) for the plan's hand-solvable case and against a 60-digit `Decimal` reference over the whole admitted parameter domain (volumes from a subnormal cube up to a cube just under `DBL_MAX`), and runs a mutation kill matrix: nineteen deliberately wrong variants (descending-ID ties, `r+1`, `r+0`, ascending proxy, ranking by Mpeak, materialising `n_r` first, comparing the exponentiated double instead of the log, casting `ShamMpeak` without the `FLT_MAX` check, flushing a subnormal result to zero, wrong slope sign, normalization to the eligible count, zero-peak inclusion, Type 2 exclusion, positional instead of per-ID assignment, clipping instead of failing, Type 2 peak updates, float32 evaluation, dropping malformed ineligible entries, inventing fallback IDs) must each be detected by at least one test. It measures and records `exp(log(100000.0))` on the running platform, the exact mass endpoint, the roundoff band around it, the subnormal-output bit pattern and the huge-box failure, sweeps the accepted parameter corners to count how many fail a snapshot by specification and on how many the superseded `n_r`-first form would have failed an in-range mass, models the parameter-string contract (`nan`, `inf`, `1e400`, `1,0`, `abc` rejected; `1e5` and `100000` identical), and exercises empty, all-ineligible, 100k-entry and malformed populations.

## Fixtures

The fixtures are maintained with the plan: a plan revision that changes a binding sentence, an authorized path or a cited line anchor updates the matching fixture in the same change, with the reason recorded in the planning review record.

- `fixtures/critical_phrases.txt`: `slice|phrase` lines that must reach both the Developer and Reviewer prompts verbatim. Add a line when a binding sentence is added to the plan; the guard fails if a later edit loses it.
- `fixtures/witness_paths.json`: per-slice paths an implementation plausibly changes (must be authorized) and paths that non-goals or other slices forbid (must be rejected), plus paths that are unauthorized everywhere.
- `fixtures/anchors.json`: the planning baseline (`planning_baseline`, the one place the current baseline commit is recorded; after any commit outside the planning surface, review the drift, record the review in the checks record and move that value; nothing in the plan changes, and `plan.baseline_hash_not_embedded` fails if the plan ever carries it), the plan's `path:start–end` citations with identifiers that range must contain, identifiers the plan names by symbol, plan-named new paths that must not exist at the baseline, and envelopes a revision removed that must not exist either.

## Limitations

The PM library is imported from outside the repository; if it changes, these checks measure the new behaviour, which is the point. The generated header in the working tree is whatever the last `make generate` produced (sage16 at the time of writing), so the SHAM-specific fields are not compiled against and the scratch-sort probe reads `StellarMass` instead; the script reports this as a SKIP. The oracle is an independent re-implementation of the specification, not a test of any C module; agreement between the two says the specification is internally consistent and its tests are discriminating, nothing more. Its libm measurements come from the Python interpreter's platform libm, which is the library a C build on the same machine links, and say nothing about another platform's libm. The parameter-string model uses Python's `float`, which matches `strtod` for the strings the plan names but not for hexadecimal literals or for `ERANGE` on subnormal results. The drift check is conservative by construction: a bare directory name, a PM bookkeeping path or any file outside the five planning-surface entries counts as drift even where PM itself would ignore it.
