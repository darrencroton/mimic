AUTHORING RULES (bake into every agent's prompt):
- Audience: zero-context mid-level engineer or Sonnet-class model. Imperative runbook voice; copy-pasteable commands; every jargon term defined once; tables and checklists; each skill says when NOT to use it and which sibling to use instead.
- Format: `.claude/skills/<name>/SKILL.md`, YAML frontmatter with `name` and a trigger-rich `description` (exactly when a model should load it).
- Design for progressive disclosure: keep each `SKILL.md` concise enough to load cheaply, put large reference inventories or worked examples in one-level `references/` files, put deterministic repeated checks in `scripts/`, and avoid auxiliary files that do not help an agent act. Do not create extra `README.md`, changelog, installation guide, or process-retrospective files inside skills.
- GROUND TRUTH ONLY: verify every command, flag, path, generated filename, test name, YAML key, Make target, and claim against the repo before stating it. Wrong runbooks are worse than none.
- Embed knowledge; don't reference private/user-specific paths as load-bearing sources.
- Date-stamp volatile facts; end each skill with a "Provenance and maintenance" section containing one-line re-verification commands for anything that may drift.
- No oversell: unproven things stay labeled open/candidate. Nothing may contradict the project's own manifest/rules, and no skill may route around Mimic's change-control.
- Respect generated-code boundaries: never tell users to hand-edit `generated/` outputs; route to metadata/generator changes and verified regeneration.
- Respect package ownership: model-specific physics belongs under `models/<model>/`, simulation/catalog concerns under `simulations/<simulation>/`, framework infrastructure under `src/`, plots under `plot/mimic-plot/`, and shared tests under `tests/` unless the repo proves a narrower rule.
- Respect selector consistency: use the same `MODEL=<name>` and `SIMULATION=<name>` pair for `generate`, `validate-modules`, tests, build, and run examples unless the skill is explicitly demonstrating a mismatch failure.
- Respect test-output discipline: long test suites must be captured/summarized, exit codes checked, and failures treated as real defects.
- Each skill should include a tiny "first action" checklist for a smaller model: what to read first, what command to run first, and what evidence to gather before editing.
- Write ONLY inside `.claude/skills/`; the rest of the repo is read-only; no mutating git commands.
