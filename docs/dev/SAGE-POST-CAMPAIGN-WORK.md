**Date:** 2026-11-08 (written by the post-campaign review session of campaign sage26).

- **What the package is.** `models/sage26/` ports SAGE26 (`sage-home/SAGE26` at `11b1ae8`) as 26 runtime modules. Under the ten-patch core-alignment set (`models/sage26/tools/core-alignment/`, applied only in a throwaway clone) it reproduces SAGE26 bit for bit in every compared property at all 56 snapshots of mini-Millennium; on Mimic's own core it is SAGE26 up to the random realisation of the CGM-regime draw (27 of 106 population readings beyond `sage16`'s figures at z = 0, largest CGMgas +1.75%). `models/sage26/README.md`, *Agreement with SAGE26*, is the durable record; the CHANGELOG's *Claims and limits* restates it.
- **How a physics change is checked.** Three gates, all in the repository, and one measurement that needs the campaign's reference output:
  1. The function-level oracle: `make MODEL=sage26 SIMULATION=mini-millennium tests-unit` compares 1,044 fixture pairs over 24 modules bit for bit on the pinned Apple clang toolchain (SKIP elsewhere; `models/sage26/modules/_tests/oracle/README.md`). A change that is meant to leave the shipped physics unchanged must leave every oracle comparison passing with no new SKIP; a change that is meant to alter a routine must regenerate exactly the fixtures that routine owns (`regenerate.sh`, which needs the staged SAGE26 source) and no others.
  2. The scientific baseline: `make MODEL=sage26 SIMULATION=mini-millennium tests-scientific` against `models/sage26/modules/_tests/baseline/` (strict 1e-6 on macOS; the Linux floor is 5.5e-4 and CI's relaxed gate is 1e-3).
  3. The reference-identity byte gate for `sage16` and `halos-only`: `make tests-reference-identity REFERENCE_COMMIT=<the commit before the change>` (eight legs, both drivers; `tests/README.md`). Every `sage16` item below must pass it unchanged unless the item says otherwise, and `make tests-scientific` on the default pair must match strictly.
  4. The T1 instrument against SAGE26's own output: `models/sage26/tools/compare_sage26.py` with the T1 reference (SAGE26 at `11b1ae8`, default configuration, mini-Millennium, eight snapshots; SHA-256 pinned in the comparator as `T1_REFERENCE_SHA256`). The reference is not in the repository; the campaign's copy is at `/Volumes/Internal/results/sage26-campaign/workspace/e01-reference/out/` on the owner's Mac (the campaign dossier's `validation/e01-reference/receipt.md` hashes it), and it can be regenerated from the staged SAGE26 source at `/Volumes/Internal/results/sage26-campaign/reference-src/` as the comparator's README describes. Core-aligned bit parity is the strong check for an item that must not move the physics; the own-core population readings (the 106 readings of the README) are the check for an item that is meant to.

## The work, in recommended order

Each item: what is wrong or missing, where (cited at `main` after the merge; `R/` is SAGE26's source root at `11b1ae8`), why it was deferred, what to do, and how to accept it. Effort: S under half a day, M a day, L more.

### A. Package physics in non-default configurations (`sage26`, and the same in `sage16`)

**A1. The optional-supernova gas cap (HIGH; M).** `sage26_apply_star_formation_supernova` makes its ordering check on the supernova calculator conditional on that module being configured (`sage26_apply_star_formation_supernova.c`, the `sn_present` branch of `init()`), and the only place that caps `stars + reheated` at the cold gas is the calculator itself (`sage26_calculate_supernova_feedback.c`, the block headed "Can't use more cold gas than is available", SAGE26 `R/src/model_starformation_and_feedback.c:775-779`). With the calculator left out of a run file nothing caps star formation, so a long substep can drive `ColdGas` negative. SAGE26 applies the cap unconditionally (`:775-778`, called at `:1054`). `sage16` has the identical structure (`models/sage16/modules/sage_apply_star_formation_supernova/`, `sage_calculate_supernova_feedback/`). Deferred because the fix changes the written physics of a configuration that initialises today. Do: in both packages, apply the budget cap in the apply module when the calculator is absent (so the default pipeline's arithmetic is untouched, the calculator still owning the cap when present), and add one integration case per package that runs the pipeline without the calculator and asserts no negative `ColdGas`. Accept: oracle and baselines unchanged; the reference-identity gate unchanged for `sage16`; the new cases pass.

**A2. `AGNrecipe 0` as SAGE26's off switch (M).** SAGE26 gates black-hole growth on `AGNrecipeOn` at `R/src/model_mergers.c:262-264` and `R/src/model_disk_instability.c:101-103`; the package's `sage26_quasar_mode` grows the black hole on every merger and instability regardless (`sage26_quasar_mode.c`, the merger-event branch calling `mimic_apply_black_hole_growth`; it reads no `AGNrecipe`), gating the channel on the module's presence instead. The README now says so (the `AGNrecipe` row and the radio and quasar module READMEs), so a user is not misled; the faithful fix is for `sage26_quasar_mode` and the instability path to read `AGNrecipe` and skip growth at 0, which changes no default output (the default is 2). Do that, and decide **A3** with it. Accept: oracle unchanged (no fixture exercises `AGNrecipe 0` growth), baselines unchanged, one unit case for the skip.

**A3. `AGNrecipe 1` and `3` (S or M).** Accepted at initialisation but not SAGE26's expressions (`models/sage26/README.md`, *Departures from SAGE26* and the parameter row: "1 empirical and 3 cold cloud, not SAGE26's forms but the same expressions as `sage16`'s"). The package's rule for every other unported option (the campaign's D33: `BulgeSizeOn` accepts 0 or 3 only) is to refuse. Do: refuse 1 and 3 in `sage26_radio_mode_heating`'s `init()` with a message naming the two accepted values, or port SAGE26's expressions (`R/src/model_cooling_heating.c`, the `AGNrecipeOn` branches) with oracle fixtures for them. Refusing is recommended; porting is only worth it if a user asks. Accept: default run files unchanged; a unit case per refused value.

**A4. `pow(10, x)` in the FFB threshold (S).** `models/sage26/shared/sage_ffb_regime.h`, the return of the threshold function, keeps `pow(10.0, log_Mvir_ffb_code)` where SAGE26's object calls `__exp10` (`R/src/model_regimes.c:312`); the package's own `mimic_sage_exp10` (`shared/sage_cooling_physics.h`) exists for exactly this and is used at the two cooling sites. The header's own comment records that `pow` equals `__exp10` at every mini-Millennium redshift and every fixture, but is one ulp apart at micro-Uchuu's snapshot 3, and the classifier's decision is `draw < f_ffb`, so on another simulation a row at the boundary flips `FFBRegime`. Deferred because it can change a written value off mini-Millennium. Do: call `mimic_sage_exp10` there; state in the header that on non-Apple platforms both sites fall back to `pow`. Accept: oracle unchanged (none should change on mini-Millennium; if any does, the fixture was at a boundary and the regenerated value is the correct one), baselines unchanged, and one micro-Uchuu spot check if the dataset is to hand.

**A5. The FFB transaction's test trace (S).** `sage26_ffb_star_formation.c` declares and initialises a `struct Sage26FfbStarFormationTrace` on every production call and passes its members to the shared helpers (`&t.sf_caps`, `&t.feedback`, `&t.commit`, `&t.yield`), while the shared headers document those arguments as "NULL in production" (`shared/sage_sf_feedback_physics.h`, `sage_ffb_feedback_physics.h`, `sage_metal_yield_physics.h`). Either build the trace only when a test observer is installed, or correct the four contract lines. Deferred because it restructures the FFB transaction's code path. Do the first (the observer already exists for the tests). Accept: oracle and baselines unchanged; the FFB unit tests still observe the trace.

**A6. The SFR-history bin product (S).** `shared/sage_sfr_history.h`, `mimic_sage_sfr_step_bin`, computes `step * MIMIC_SAGE_SFR_STEPS` in `int`; `SubSteps` is read with no upper bound (`src/core/read_parameter_file.c`, the `SubSteps` parse). Unreachable in practice (overflow needs `SubSteps` above about 2e8) but unbounded. Do: compute in 64-bit, or bound `SubSteps` where the core reads it (a core change; see C2). Accept: oracle unchanged.

**A7. Inherited `sage16` lessons that are code.** The campaign's D41 asked for `sage16 lesson:` entries and none were written; the review reconstructed them (the dossier's `post-campaign/sage16-lessons.md`). The ones that are code changes in `sage16`: A1 above (the cap) is the only physics one. The others are tests (its model-package tests are binary-bound, so no horizontal package runs them: the pathway's *Recorded residuals*), presentation (its figures carry the quirks the sage26 plots pass fixed in both packages) and marking (44 `SAGE parity:` lines against sage26's 239, so sage16's deliberate quirks are less completely marked). None is scheduled here beyond A1; they are listed so the next `sage16` pass starts from them.

### B. Records, not code

**B1. x01's package findings with no compared effect.** From the campaign's alignment experiments (dossier `validation/x01-*/HANDOFF.md`, `validation/c07-*/HANDOFF.md`): the merger-clock event's `Age` is rebuilt by addition (`shared/sage_merger_clock.h`), `Mvir` is float-rounded there, `MergTime` is never compared by the instrument, and one unattributed radius difference remains at the R1 rung (halo 10233590, snapshot 63, 1.7e-4 relative). None reaches a compared property on mini-Millennium. Do nothing unless a later reference differs there; this paragraph is the record.

**B2. The CGM-regime draw's key.** The package's draw is keyed on `(UniqueGalaxyID, snapshot, salt, ordinal)` (`shared/sage_keyed_draw.h`; the campaign froze it as D36). If a future SAGE26 keys its own draw, re-key the package to match so the two codes can be compared on Mimic's own core without the alignment set. The hand-back to the SAGE26 team (section E) asks for exactly that.

### C. Core changes (the owner's reserved class; each a design question, not a defect)

**C1. `NaN` parameters (S).** `VALIDATE_RANGE_INCLUSIVE` and its siblings in `src/module_system/parameter_helpers.h` test `value < min || value > max`, which `NaN` passes, and `parse_double_strict` in `src/core/module_registry.c` accepts `strtod`'s `nan`. Four sage26 initialisers add their own `isfinite` check; the rest, and every `sage16` module, do not. The right fix is one `isfinite` test in the core helper (one line in each range macro, or one in `parse_double_strict`), after which the four package checks can go. Accept: a unit test in `tests/unit/` that a `nan` parameter is refused; every package's default run files unchanged.

**C2. A minimum-substeps run-file key (L; design).** Alignment item 04 (`models/sage26/tools/core-alignment/items.md`, item 04) is SAGE26's floored substep rule, which Mimic's timestep schemes do not have; left out of the set it accounts for 180 failed thresholds against SAGE26. A general `SubSteps` minimum (or a named scheme) in the run file would let a user reproduce SAGE26's floor without a patch. Vision principle 4 (one coherent processing model) applies: it must be a scheme the core owns, not a package knob. Decide first whether it is wanted; if so, plan it with the bound on `SubSteps` from A6.

**C3. `mimic` exits 0 with every tree file missing (S).** With `input.first_file` to `last_file` naming files that do not exist, the vertical driver logs and completes with no galaxies and exit status 0 (the campaign's E25; the owner left it for the review as D51(5)). Do: refuse to start when no requested file exists (and warn when some do not), in `src/core/vertical_driver.c`'s file loop or where the reader opens them. Accept: an integration case with a missing range expecting a non-zero exit.

**C4. A fixed-length array property type (L; design).** The property generator has no array type, so SAGE26's per-substep star-formation histories became 60 scalar properties (`models/sage26/model_properties.yaml`, `SfrDiskBin0` to `SfrDiskBin9` and their metal and bulge companions). A `TYPE_MAP` array type (C array field, HDF5 compound array member, binary layout, `output_convert` per element) is a core generality item that the next ported model with histories will hit again. Design first; the `sage26` migration would change its output schema, so it is a versioned change.

**C5. `output_convert` cannot express left-associated unit chains.** SAGE26 writes several rates through chains like `(x / UnitTime) * UnitMass / SEC_PER_YEAR` whose rounding differs from one factor; the package reproduces them with a finalizer module (`sage26_finalize_cooling_heating`; the campaign's D39). An `output_convert` that accepts an ordered factor list would remove the finalizer. Low value unless another port needs it; recorded.

**C6. `MAX_MODULES` as a build-time check (S).** `src/core/module_registry.c` sizes two arrays by `MAX_MODULES` (64 since the import; 37 used by `sage26`), each bounds-checked before every write. A `_Static_assert` against the generated module count would make the limit a build-time fact instead of a runtime refusal. Cosmetic; do it if touching the registry.

### D. Measurement items that need more than the repository

**D1. The `sage26` Linux floor.** Recorded beside the baseline (5.5e-4 relative at worst, CGMgas at snapshot 63, Ubuntu 24.04 gcc 13 arm64, 2026-11-08). If a Linux host is ever the owner's primary, measure the floor on x86-64 too and decide whether `sage26` deserves its own committed Linux baseline instead of the relaxed gate.

**D2. The oracle on a newer Apple clang.** The oracle comparisons now SKIP on any toolchain other than the pinned Apple clang build string and macOS version. When the owner's toolchain moves, regenerate the fixtures from the staged SAGE26 source with the new toolchain (the oracle README, *Regenerating*), compare old against new fixture by fixture, record the differences (expected: last-bit `libm` differences only), and re-pin.
