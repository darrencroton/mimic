### W2. Fix the Makefile `.git/HEAD` prerequisite (worktree/tarball builds)

Confirmed outstanding: `Makefile:323` is `$(GIT_VERSION_H): .git/HEAD .git/index` — literal paths with no rule behind them, so a build from a git worktree (where `.git` is a file) or an exported tarball dies with `No rule to make target '.git/HEAD'`. Phase 4b hit this directly, and Phase 5's identity gate needs two builds. The recipe itself already degrades gracefully (`git rev-parse … || echo 'unknown'`); only the prerequisites fail hard.

The pathway's proposed fix is coherent with the rest of the Makefile — `:323` is the **only** `.git` literal in it:

```make
GIT_DIR := $(shell git rev-parse --git-dir 2>/dev/null)
$(GIT_VERSION_H): $(wildcard $(GIT_DIR)/HEAD $(GIT_DIR)/index) | $(GENERATED_BUILD_DIR)
```

In the tarball case the wildcard collapses to no prerequisites and the header is generated once with `unknown` values, consistent with the recipe's existing fallback (`$(GIT_VERSION_H)` is an order-only-adjacent prerequisite of every object at `Makefile:374`, so "built once, never refreshed" is acceptable there and strictly better than the current hard failure).

**Acceptance:** `git worktree add <dir> && make` inside the worktree builds; a normal-checkout build is unchanged and `git_version.h` still refreshes when HEAD moves; a build from `git archive` output completes with `unknown` version fields.

### W5. Fixture-tooling and test-harness hardening (recommended now; Phase 5 extends these tests)

All verified still outstanding on the branch. None is a correctness defect today; each will bite precisely when Phase 5 adds snapshot-path tests and fixtures, which is why they belong before Phase 5 rather than inside it. In recommended order of value:

1. **`expect_fatal` capture truncation** (`test_unit_snapshot_reader_open.c:466-535`): detect a full buffer and fail with an explicit "output truncated at 16383 bytes — raise the buffer" message rather than a misleading "missing fragment". (The Deferred list's "deadlock" is wrong — finding 9; a ≥16 KB child dies of SIGPIPE and fails loudly.)
2. **`FIXTURE_MAX_HALOS` unchecked reads** (`:68`, `:429-449`, `:990-992`): `read_halo_column()` does a full-extent `H5Dread` into a fixed 6-element buffer with no dataspace-extent check — a larger future fixture silently overflows the stack buffers. Add an extent assertion against `FIXTURE_MAX_HALOS` before every read.
3. **Link-width `_Static_assert`** (`src/io/snapshot/read_snapshot_hdf5.c:755,824`): the link validator reads members via `*(const int *)` with `offsetof` and nothing ties those members to `int`. Add `_Static_assert(sizeof(((struct RawHalo *)0)->FirstProgenitor) == sizeof(int), …)` for the five link fields so a future package typing a link wider is a compile error, not a truncated validation.
4. **Transactional `regenerate()`** (`create_snapshot_fixture.py:625-640`): write the re-chunked set to a temp directory and rename into place, so a mid-run failure cannot leave a partial fixture beside a stale manifest.
5. **Wire the conformance checker into a test target**: zero references to `check_fixture_conformance.py` or `create_snapshot_fixture.py` exist in the Makefile or test registry, so the committed fixture is protected only by manual re-runs. Cheapest wiring: a package-local test (registered via `simulations/micro-uchuu-snapshot/_tests/`) or a `make` hook that runs the checker against `_tests/data/`.
6. **`stage_fixture()` failure-path cleanup** (finding 7): remove the `mkdtemp` directory before each early return.

7. **`check_filters()` chunkedness** (`check_fixture_conformance.py:111-127`): the docstring was reworded on this branch (it now flags that chunk *shape* is deliberately unchecked), but it still states "the storage contract is chunked" while the function checks only compression/filter properties and never asserts `dataset.chunks is not None` — a contiguous dataset would pass. The frozen spec's storage contract requires chunked layout (`docs/dev/SNAPSHOT-HDF5-FORMAT.md:140`). Either assert chunkedness (without fixing shape — safe for the re-chunked fixture) or narrow the docstring. An earlier revision of this report called this item fully fixed; that was overstated — the wording improved, the check did not.
