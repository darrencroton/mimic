# Core-alignment set: the items

Notes for each of the ten items of the core-alignment set (`series`, `series.sha256`): what each patch changes, the SAGE26 behaviour it reproduces, why Mimic's behaviour differs, its measured contribution, and how to apply it. Every patch is a measurement instrument applied only in a disposable clone that is never merged; nothing here proposes a change to Mimic's core, to `sage16` or to the `sage26` package, and no item is assessed as a general core option.

## Conventions

- **Lines.** Mimic lines are at commit `66a3e9498561e7f2f2207267a94986e9b097b03c`, before any patch is applied; that commit is the base the set was measured on. `R/` is SAGE26 (`sage-home/SAGE26`) at `11b1ae851524baadb76cfd17e0b38f8a89c07224`, the commit the package ports. R0 and R6 are the SAGE26 configurations of the package README's [SAGE26 Configurations R0–R6](../../README.md#sage26-configurations-r0r6): R0 is SAGE26's `input/millennium.par` with its six physics switches off, R6 is SAGE26's default configuration.
- **Why Mimic differs.** Each item records a deliberate choice of the port: Mimic's core keeps its own behaviour, and the `sage26` package reproduces SAGE26's physics on top of it. The Mimic principles cited are those of `docs/VISION.md`.
- **Measured contribution.** Each item was measured left out of the full set: the other nine patches applied in `series` order (with a rebased variant where a dependent needs one, see 03 and 05), the package built with `MODEL=sage26 SIMULATION=mini-millennium`, its vertical run file run unchanged, and the output compared by `compare_sage26.py` with SAGE26's R6 output (payload-identical to the T1 reference) at T1's eight snapshots (63, 37, 32, 27, 23, 20, 18, 16). Items 01 to 09 were measured at commit `b91dcfd266d4f37599beb01d125175eeb1f0c4fb`, item 10 and the full set at `0c184929331de4775a70c8ea9808085ea163cd16`; both are `66a3e949` with only this directory changed. The full set gives `pass`: 0 failed thresholds, all 536 float property-snapshots (67 float properties × 8) and all 48 integer ones (6 × 8) bit-identical on every pair, and every galaxy matched one to one. An item's effect is a **conditional aggregate effect**, that of its absence from the full set: effects are not additive and are never summed or shared out among items.
- **How to apply.** The set is applied with `apply.sh` as the README states. One item is left out by applying the other names of `series` in order with `git apply --index`; a dependent that no longer applies without its predecessor (07 without 03, 09 without 05) needs a rebased variant with the same added lines.

## 01 `01-particle-mass.patch`: particle mass

- **Change:** `simulations/mini-millennium/simulation_info.yaml:20-23` (simulation package): `particle_mass` `value` 0.0860657 → 0.086 (`:21`). Nothing else. The core reads it into `MimicConfig.PartMass` (`src/core/read_parameter_file.c:1043-1047`) and uses it as `Len * MimicConfig.PartMass` for a subhalo, or a FoF central with a negative catalogue mass (`src/core/virial.c:47-53`), which feeds `Mvir`, `Rvir` and `Vvir`.
- **SAGE26 behaviour reproduced:** `PartMass 0.086` (`R/input/millennium.par:41`), read as a double (`R/src/core_read_parameter_file.c:161`) and used by the same rule, `Len * run_params->PartMass` (`R/src/model_halo_properties.c:31-36`).
- **Why Mimic differs:** the mini-Millennium simulation package keeps its `PartMass` 0.0860657. The value is a property of the simulation package, which Mimic selects at build time (`SIMULATION=`) and whose `particle_mass` the core reads whichever model is built with it (`src/core/read_parameter_file.c:1043-1047`; `docs/VISION.md` Principle 2, Runtime Modularity); the core's virial rule is model-independent (Principle 1).
- **Measured contribution (left out):** 250 failed thresholds; 152/536 float and 48/48 integer property-snapshots bit-identical; matching unchanged.
- **How to apply:** position 1 in `series`. No patch of the set depends on it, and it touches no file another patch touches.

## Considered and Not in the Set

- **Snapshot zero and the progenitor-snapshot redshift.** Already aligned, so it has no patch: Mimic's `SKIP_INITIAL` state arises only for a galaxy created at snapshot 0, and the mini-Millennium trees hold no halo before snapshot 8; no read of `ZZ[galaxy.SnapNum]` in `R/src` executes at R0, each being guarded by a recipe flag that is off there (`CGMrecipeOn` 0, `FIREmodeOn` 0), and the unguarded reads take the halo's own snapshot, as Mimic does (`src/core/halo_evolution.c:150`). The full set reproduces SAGE26 at every snapshot 8 to 63 without an item for it.
- **The merger backpatch of `mergeType`, `mergeIntoID` and `mergeIntoSnapNum`.** The comparator leaves these three datasets uncompared (rule 7 of [`../README.md`](../README.md); [`../field_map.yaml`](../field_map.yaml)): SAGE26 writes them by backpatching a galaxy's earlier output record after it merges in the following step, while Mimic writes each record once and a merged galaxy leaves the output, so no counterpart exists.
