# SAGE26 Function-Level Oracle

This directory holds the tooling that turns SAGE26's own physics routines into reference fixtures for the `sage26` package. The oracle compiles SAGE26's physics sources unchanged, calls one SAGE26 routine on an explicit input, and records exactly what it computed: the routine's return value, every field it writes, and every intermediate value the package carries between modules. A package module's unit test can then run the same input through its `process()` entry and compare field by field, bit for bit.

It is reference tooling, not Mimic code: it lives under a `_tests/` path, which the Makefile's package source scan excludes (`! -path '*/_tests/*'`), and it builds into its own executable that never links Mimic code.

| File | Purpose |
|---|---|
| [`build.sh`](build.sh) | Compiles SAGE26's physics sources and each oracle main, `oracle_c03.c` into `output/oracle/oracle_c03` and likewise for c04 and c05 |
| [`regenerate.sh`](regenerate.sh) | Checks the manifest, runs `build.sh`, rewrites every fixture output from its input |
| [`oracle_c03.c`](oracle_c03.c) | The oracle main for the c03 (baryon supply) routines |
| [`oracle_c04.c`](oracle_c04.c) | The oracle main for the c04 (cooling and radio heating) routines; `build.sh` builds it the same way into `output/oracle/oracle_c04` |
| [`oracle_c05.c`](oracle_c05.c) | The oracle main for the c05 (star formation, feedback, instability, histories and outflow) routines; `build.sh` builds it the same way into `output/oracle/oracle_c05` |
| [`oracle_c06.c`](oracle_c06.c) | The oracle main for the c06 (merger clocks, mergers, black holes, bursts, disruption and their driver arithmetic) routines, built the same way into `output/oracle/oracle_c06` |
| [`oracle_c07.c`](oracle_c07.c) | The oracle main for the c07 (bulge sizes) routines and the central's synchronisation transcription, built the same way into `output/oracle/oracle_c07` |
| [`fixtures.manifest`](fixtures.manifest) | Every fixture, grouped by owning module, with the count per module |

Fixtures live with the module they test, under `models/sage26/modules/<module>/_tests/oracle/`: `<name>.in` is the input, `<name>.out` the oracle's output. Both are committed test data. Inputs are written by hand or by a tool; outputs are written only by `regenerate.sh` and are never edited by hand.

## Oracle Environment

The fixtures were produced, and a bit-for-bit comparison against them is meaningful, only in this environment, which is the one that built the SAGE26 T1 reference:

- **Platform:** macOS 27.0.1 (build 26A434) on arm64 (Apple silicon), with the system C library and **macOS libm** (`pow`, `sqrt`).
- **Compiler:** Apple clang version 21.0.0 (clang-2100.4.1.1), target `arm64-apple-darwin27.0.0`.
- **Flags:** the SAGE26 reference build's recorded flags, unchanged except for the value of `ROOT_DIR`:

  ```text
  -DROOT_DIR='"<staged SAGE26 root>"' -DVERBOSE -DGSL_FOUND -DHDF5 -DGITREF_STR='"unknown"'
  -O2 -march=native -std=gnu99 -fPIC -I/opt/homebrew/Cellar/gsl/2.8/include
  -DUSE_BUFFERED_WRITE -I/opt/homebrew/include -g -Wextra -Wshadow -Wall
  -Wno-unused-local-typedefs
  ```

  `oracle_c03.c`, `oracle_c04.c` and `oracle_c05.c` additionally get `-I<staged SAGE26 root>/src` for SAGE26's headers. The link uses GSL 2.8 (`-L/opt/homebrew/Cellar/gsl/2.8/lib -lgsl -lgslcblas` with an rpath) and `-lm`, as the reference link did; the reference also linked HDF5, which none of these sources call.
- **Floating-point contraction:** clang's default (`-ffp-contract=on`), under which a multiply and an add or subtract *within one C expression* may be fused into a single `fma` on arm64. No flag changes it, in SAGE26's build or here.
- **SAGE26 source:** commit `11b1ae851524baadb76cfd17e0b38f8a89c07224`, staged read-only at `/Volumes/Internal/results/sage26-campaign/reference-src`.

**A bit-for-bit claim holds only for the same compiler, the same flags, the same contraction behaviour and the same libm.** A different compiler or version, a different optimisation level or `-march`, a different `-ffp-contract`, or a different libm can change the last bits of a result legitimately. On any other platform the fixtures are still a close reference, but an exact-match test should report SKIP rather than FAIL.

`build.sh` refuses to build when `clang --version` or the staged source's commit differs from the above; `ORACLE_ALLOW_ANY_TOOLCHAIN=1` overrides that for experiments, and outputs built that way are not reference fixtures.

## What Gets Compiled

`build.sh` compiles the twelve sources SAGE26's own `tests/Makefile` links its unit tests against, in that order: `core_utils.c`, `model_misc.c`, `model_h2_chemistry.c`, `model_halo_properties.c`, `model_regimes.c`, `model_starformation_and_feedback.c`, `model_cooling_heating.c`, `model_reincorporation.c`, `model_infall.c`, `model_disk_instability.c`, `model_mergers.c`, `core_cool_func.c`. Each is compiled from the SAGE26 root as `src/<name>.c`, as the reference build did. Nothing is written in the SAGE26 tree; objects go to `output/oracle/obj/` and the executable to `output/oracle/oracle_c03` (the worktree's git-ignored `output/`). `SAGE26_SRC` and `ORACLE_OUT` override the two locations. `oracle_c04.c` and `oracle_c05.c` are compiled with the same flags and linked against the same twelve objects, in the same way, into `output/oracle/oracle_c04` and `output/oracle/oracle_c05`.

## Regenerating

```bash
sh models/sage26/modules/_tests/oracle/regenerate.sh
```

`regenerate.sh` first checks that `fixtures.manifest` is self-consistent and agrees exactly with the `.in` files on disk, then runs `build.sh`, then runs the matching oracle main on every listed fixture, and finally checks that no `.out` lacks its `.in`. Fixtures of the four c04 modules (`sage26_calculate_cooling_budget`, `sage26_radio_mode_heating`, `sage26_apply_cooling` and `sage26_finalize_cooling_heating`, the `C04_MODULES` list in `regenerate.sh`) run through `output/oracle/oracle_c04`; every other (c03) fixture runs through `output/oracle/oracle_c03`, except that a fixture whose `routine` line names a c05 routine (the `C05_ROUTINES` list) runs through `output/oracle/oracle_c05`, whichever module owns it: `sage26_finalize_cooling_heating` holds c04 and c05 fixtures side by side. Each run writes to a fresh temporary file under `ORACLE_OUT`, which is moved into place as `<name>.out` only if the oracle exited 0 and the file is a complete output: the header, format and routine lines, at least one typed field, every later line a typed field, and a final newline. Otherwise the script stops non-zero and leaves the old output untouched. The exit status alone is not enough: SAGE26's `ABORT(0)` (`R/src/macros.h`), which `read_cooling_functions()` uses on a missing or malformed cooling table, exits with status 0 and writes nothing. Outputs are deterministic: running it twice gives byte-identical outputs, the c03 outputs are unaffected by the c04 group, and the c03 and c04 outputs by the c05 group. To add a fixture, write its `.in`, add it to `fixtures.manifest` (and raise the module's count), and run `regenerate.sh`.

Run one fixture by hand with its matching oracle main, `output/oracle/oracle_c03 <input> <output>` for a c03 fixture, `output/oracle/oracle_c04 <input> <output>` for a c04 one or `output/oracle/oracle_c05 <input> <output>` for a c05 one.

## Fixture File Format

A fixture file is UTF-8 text, one statement per line. `#` starts a comment that runs to the end of the line; blank lines are ignored. The first statement is the format line, the second names the routine, and every other statement is one typed, named field:

```text
# free-text description and provenance
format sage26-oracle-fixture 1
routine reincorporate_gas
f64 params.ReIncorporationFactor 0x3fc851eb851eb852  # 0.19
i32 call.effective_steps 10
f32 galaxy[0].Vvir 0x43480000  # 200
```

| Type | Value | Meaning |
|---|---|---|
| `f32` | `0x` + exactly 8 hex digits | The IEEE-754 binary32 bit pattern of a `float` |
| `f64` | `0x` + exactly 16 hex digits | The IEEE-754 binary64 bit pattern of a `double` |
| `i32` | decimal | A 32-bit integer |

The hexadecimal value is the exact bit pattern, not a C99 `%a` literal; the decimal after `#` is for reading only and is never parsed. Names are unique within a file. The oracle rejects a missing field, a field of the wrong type, a malformed bit pattern (anything but `0x` and exactly 8 or 16 hex digits), and an input field its fixture reader for the selected routine does not consume, so a misspelt name cannot be silently ignored. The reader consumes a superset of what SAGE26 reads: some fields, such as `galaxy[i].Type`, are set for the Mimic side although the SAGE26 routine never reads them.

### Reader Limits

The package's fixture reader (`models/sage26/modules/_tests/sage26_oracle_fixture.h`, which every module's oracle test uses) reads every statement of a fixture file and every line of `fixtures.manifest`; it never stops early or cuts a value. Its limits are fixed arrays, and an input beyond any of them is refused with a message naming the limit, so the test fails rather than reading part of the input:

| Limit | Value | Refused when |
|---|---|---|
| `ORACLE_MAX_FIELDS` | 2048 | a fixture file has more field statements |
| `ORACLE_MAX_FIXTURES` | 256 | a module has more `fixture` lines in the manifest, or its `module` line declares more |
| `ORACLE_MAX_LINE` | 1024 | a line of a fixture file or the manifest has 1024 or more characters before its newline |
| `ORACLE_MAX_NAME` | 128 | a field name, value, routine name or manifest token has 128 or more characters |
| `ORACLE_MAX_PATH` | 512 | a fixture file's path has 512 or more characters |

An `i32` value outside the 32-bit range, and a read error, are refused too. The headroom over the largest use when the limits were set was fourfold: the largest output has 511 fields (`tr_jp_type0_orphan_history_merge`) and the largest module, `sage26_resolve_mergers_and_disruption`, owned 64 fixtures (96 since c07). c07's largest output has 564 fields (`merge_s3_minor_spheroid`, `merge_s3_r1_snap63_minor_spheroid`, `merge_s3_rounding_float_sums_spheroid`). Each module's oracle test still fails when the fixtures found on disk, the fixtures listed and the count the manifest declares disagree. The reader's self-test, `models/sage26/modules/_tests/test_unit_sage26_oracle_reader.c`, pins each limit in the table at its boundary or one past it, and each refusal by its message. It checks that manifests of 200 and 256 fixtures and files of 1500 and 2048 fields are read in full. It checks that the following are refused naming their limit: one fixture line or declared count over `ORACLE_MAX_FIXTURES`, one field over `ORACLE_MAX_FIELDS`, an overlong manifest or fixture line, a 128-character name, and a path over `ORACLE_MAX_PATH`. It checks that a truncated manifest and a listed fixture without its `.out` fail the count check, and that the following are refused: a fixture cut mid-statement or after its format line, an out-of-range `i32`, and a read error (a directory given as the manifest or fixture). The oracle mains have their own input limits (`MAX_FIELDS` in each): 512 input fields for `oracle_c03` and `oracle_c04`, 1024 for `oracle_c05`, `oracle_c06` and `oracle_c07`; a larger input stops the oracle with an error stating the limit, and is never truncated.

### Field Names

| Prefix | Meaning |
|---|---|
| `params.<Name>` | A `struct params` member of that name |
| `galaxy[<i>].<Name>` | Member `<Name>` of SAGE26's `struct GALAXY` at index `<i>` of the galaxy array |
| `halo.<Name>` | A `struct halo_data` member (the single halo the call reads) |
| `call.<name>` | A call-site quantity of `core_build_model.c` (redshift, substep count, Age entries, indices, the infall budget) |
| `return.<name>` | (output) the routine's return value |
| `intermediate.<name>` | (output) a value formed at the call site or carried between package modules |

Galaxy fields use SAGE26's names. Where the package's property differs: `EjectedMass` is the package's `EjectedGas`, `MetalsEjectedMass` is `MetalsEjectedGas`, `DiskScaleRadius`, `ICS`, `MetalsICS`, the ICS history fields, `CGMgas`, `MetalsCGMgas` and the other reservoirs keep their names. On the Mimic side `Mvir`, `Rvir` and `Vvir` are core-owned halo fields and `Spin` is the simulation package's halo property (`halo.Spin[j]` here). SAGE26 holds `Mvir`, `Rvir` and `Vvir` as `float`; the Mimic side is given the exactly widened `double` of the same bit pattern.

Core-owned quantities a routine reads are never derived by the oracle: `params.G` and `params.Hubble`, the cosmology (`params.Omega`, `params.OmegaLambda`), the reionization scale factors (`params.a0`, `params.ar`), `call.Zcurr`, the Age entries and the halo fields are all explicit inputs.

The oracle initialises every field its reader consumes, a superset of the fields the routine reads. Every other struct member is poisoned with all bits set before the call (NaN for floating point, -1 for integers), so a read of a member the input did not set would usually surface as NaN in the output; not always, since a NaN can be compared away (every ordered comparison with it is false) or overwritten before it reaches an output.

## Routines

Each fixture describes one call, with the arithmetic SAGE26's call site performs around it (`R/` is the staged SAGE26 root). All fixtures describe the R0 configuration (`ReionizationOn 1`, `CGMrecipeOn 0`, `BaryonFrac 0.17`, `ReIncorporationFactor 0.19`, `Reionization_z0 8`, `Reionization_zr 7`, Millennium cosmology and units), but each `.in` carries only the params its routine's reader consumes, so the R0 values of the others are implied rather than written. For example, `do_reionization` fixtures carry no `params.ReionizationOn`: SAGE26 evaluates that gate at the caller (`infall_recipe`, `strip_from_satellite`), and on the Mimic side it is the package's choice to run `sage26_reionization`; `add_infall_to_hot` and `reincorporate_gas` fixtures carry `params.CGMrecipeOn` but no reionization params; `get_disk_radius` fixtures carry no params at all. Likewise no fixture sets `Regime`: SAGE26 does not read it on R0, the oracle leaves it at its poison value -1, and -1 is what every R0 galaxy holds (it is initialised to -1 and only reclassified when `CGMrecipeOn` is 1).

| Owning module | Routine | Call-site arithmetic reproduced | Output |
|---|---|---|---|
| `sage26_reionization` | `do_reionization` (`R/src/model_infall.c:286`) | none | `return.reionization_modifier`; `intermediate.HaloBaryonFraction` = modifier × `BaryonFrac` |
| `sage26_prepare_infall_budget` | `infall_recipe` (`R/src/model_infall.c:67`) | the call at `R/src/core_build_model.c:415` | `return.InfallingGas`; the modifier and `HaloBaryonFraction` it used; per galaxy the ejected, ICS (with history), CGM and hot reservoirs after the call |
| `sage26_apply_infall` | `add_infall_to_hot`, non-CGM branch (`R/src/model_infall.c:351`) | `infallingGas / effective_steps` (`R/src/core_build_model.c:488`) | `intermediate.infallingGas_per_step`; the ejected and hot reservoirs |
| `sage26_reincorporation` | `reincorporate_gas` (`R/src/model_reincorporation.c:44`) | `deltaT = Age[SnapNum] - halo_age`, the `ReIncorporationFactor > 0.0` gate, `deltaT / effective_steps` (`R/src/core_build_model.c:479`, `:490-492`) | `intermediate.deltaT`, `intermediate.dt`, `intermediate.reincorporate_gas_called`; the ejected and hot reservoirs |
| `sage26_satellite_stripping` | `strip_from_satellite`, non-CGM routing (`R/src/model_infall.c:225`) | the Type 1 gate (`R/src/core_build_model.c:493-498`) | the satellite's modifier and `HaloBaryonFraction`; `intermediate.strip_from_satellite_called`; hot and CGM reservoirs of every galaxy |
| `sage26_set_disk_scale_radius` | `get_disk_radius` (`R/src/model_misc.c:203`) | the float store into `DiskScaleRadius` (`R/src/core_build_model.c:297`) | `return.r_disk` (double) and `galaxy[0].DiskScaleRadius` (float) |

`HaloBaryonFraction` is the double product `reionization_modifier * BaryonFrac`, rounded once. SAGE26 forms the same product as the leading term of `reionization_modifier * BaryonFrac * Mvir - S` in `infall_recipe` (`R/src/model_infall.c:128-130`) and `strip_from_satellite` (`:243-244`), so the package may carry it between modules and finish the expression with the halo's `Mvir`. **The finish must stay fused.** In the oracle build (and the reference build, whose machine code is identical) clang's default contraction compiles that expression on arm64 to an `fmul` (the product, rounded once) followed by a single fused multiply-subtract: `fnmsub` (`product * Mvir - S`) in `infall_recipe`, and `fnmadd` in `strip_from_satellite` (AArch64 `fnmadd d, n, m, a` computes `-(n * m) - a`; here `n` is the product, `m` the widened `Mvir` and the addend register `a` holds `-S`, an `fneg` of the widened float baryon sum, so the result is `S - product * Mvir` with the `-1.0 *` folded in), before the division by the substep count. The package must therefore finish `HaloBaryonFraction * Mvir - S` fused; an unfused finish rounds the product first and generally differs (a build of `model_infall.c` with `-ffp-contract=off` reproduces `return.InfallingGas` in only 1 of the 15 budget fixtures). The two ways to fuse it are equivalent only where the compiler contracts. An explicit `fma(HaloBaryonFraction, Mvir, -S)` (with the `-1.0 *` and the substep division applied as SAGE26 orders them for stripping) is one correctly rounded operation everywhere, so it reproduces the oracle on any platform whose `fma` is correctly rounded, as C requires. A single contractible C expression fuses only where the compiler contracts it: with Apple clang on arm64 it does so at Mimic's own flags (`-O2` without `-march`; checked: `hbf * mvir - s` compiles to the same `fnmsub` as `fma(hbf, mvir, -s)`), so in the oracle environment the two agree; it does not under `-ffp-contract=off`, and a compiler targeting baseline x86-64 (no FMA instruction without `-mfma` or a `-march` that has it, e.g. GCC's default) cannot fuse it, so there only the explicit `fma` reproduces the oracle. The modifier and product recorded for `infall_recipe` and `strip_from_satellite` come from evaluating `do_reionization` on the same galaxy before the call; it reads only that galaxy's `Mvir` and the params, which neither routine writes. That evaluation happens before the call-site gate, so for a stripping fixture whose galaxy is not stripped (`orphan_not_called`: a Type 2 orphan with `Mvir` 0, giving 1/inf = 0) the recorded modifier and `HaloBaryonFraction` are values SAGE26's call site never computes: they are not SAGE26 state and a test must not assert them.

Each `.in` file states in its comments what the fixture exercises and, for fixtures taken from the R0 reference output (`r0_snap<N>_*`), which galaxy rows of which snapshot supplied the values. Those are end-of-snapshot output values used as plausible inputs, not reconstructed call-time state; their Age and substep-count inputs are plausible values, not SAGE26's own.

## Scope

The oracle covers the routines above in the R0 configuration. Branches that need a different configuration (`CGMrecipeOn 1`, `ReionizationOn 0`, `ReIncorporationFactor <= 0`) and states R0 never produces (negative gas or mass reservoirs) are outside its fixtures; tiny negative *metal* reservoirs, which R0 does produce, are included. A few fixtures are constructed edge states R0 does not produce but SAGE26's code defines exactly: -0.0 metal reservoirs (one from a hot metal debit that narrows to -0.0), a zero-excess satellite with `Mvir` 0, and exact-consumption equalities. Each such `.in` says so in its comments. They were added until the mutation sweep recorded in this slice's validation record found no strict/non-strict mutant that any input it tried could distinguish on R0. The sweep swapped every ordering comparison on the R0 path of these routines, their helpers and the call-site gates, alongside negation and drop mutants, and probed every survivor with constructed counter-inputs and a random edge-value fuzz. Four kinds of mutant survive only because of R0's settings, and the record shows inputs outside R0 that distinguish them: `Vvir >= Vcrit` and `Vvir >= (float)Vcrit` in `reincorporate_gas` (equivalent at `ReIncorporationFactor` 0.19), its reincorporation cap written `>=` (equivalent while the substep `dt` is positive), and the `CGMrecipeOn` negations (equivalent while `Regime` is -1). This is evidence from the inputs tried, not a proof that no other input distinguishes a survivor. It does not cover SAGE26's driver-level code (`join_galaxies_of_progenitors`, `evolve_galaxies`), which is static in `core_build_model.c` and not compiled here.

## The c04 Group: Cooling and Radio Heating

`oracle_c04.c` covers SAGE26's hot-halo cooling, its Bondi radio-mode heating, the cooling transfer and the end-of-halo energy normalisation, in the R0 configuration (`AGNrecipeOn 2`, `CGMrecipeOn 0`, `RadioModeEfficiency 0.08`, Millennium units). It uses the fixture format above unchanged: every value is an `f32`, `f64` or `i32` field, and the new names below follow the existing prefixes. `C` is `R/src/model_cooling_heating.c` and `B` is `R/src/core_build_model.c`.

### Cooling Tables, Loaded Once per Process

Every c04 run calls SAGE26's own `read_cooling_functions()` (`R/src/core_cool_func.c:65-99`) exactly once, before the routine, with `ROOT_DIR` naming the staged source as `build.sh` sets it, so the tables come from `<staged SAGE26 root>/src/auxdata/CoolFunctions`. The loader adds `log10(0.02)` to its static metallicity grid each time it runs, so a second call in one process would shift the grid; one fixture per process makes that impossible.

`evolve_galaxies` is static in `core_build_model.c`, which is not in the oracle's link, so the normalisation fixtures are a transcription of those lines, not a call of SAGE26 code. The normalisation's `OutflowRate` term belongs to c05; these fixtures neither set nor record it. Their inputs are `call.ngal`, `call.halo_age`, `call.Age[<snap>]` for each distinct `SnapNum`, and per galaxy `Type`, `SnapNum`, `mergeType`, `Cooling`, `Heating` and the four diagnostics; the oracle requires a galaxy with `mergeType > 0` to be `Type` 3. That rule is the Mimic package's convention, not SAGE26 behaviour: `sage26_resolve_mergers_and_disruption` sets `Type` 3 on the galaxy it merges or disrupts, while SAGE26 sets only `mergeType` when merging or disrupting (`R/src/model_mergers.c:311`, `:315`, `:902`) and sets `Type` 3 on a later snapshot (`B:243`). The transcribed SAGE26 lines read only `mergeType`.

The state written for `cooling_recipe_hot`, `do_AGN_heating` and `cool_gas_onto_galaxy` is always the same twelve fields of `galaxy[0]`: `HotGas`, `MetalsHotGas`, `ColdGas`, `MetalsColdGas`, `BlackHoleMass`, `r_heat`, `Cooling` and `Heating` (double), `tcool`, `tff`, `RcoolToRvir` and `CoolingRate`. Fields a routine does not write appear as it left them. The inputs of these three routines set the same sixteen fields: those twelve plus `Type`, `Mvir`, `Rvir` and `Vvir`. SAGE26's `r_heat` is the package's `Rheat`; the other names are the package's. The `cooling_recipe_hot` and `do_AGN_heating` inputs also carry `params.AGNrecipeOn` and `params.CGMrecipeOn`, which the oracle requires to be 2 and 0, the core-owned `params.G`, `params.Hubble_h`, `params.RadioModeEfficiency`, `params.UnitEnergy_in_cgs` and `params.UnitTime_in_s`, and (`cooling_recipe_hot` only) `params.UnitDensity_in_cgs`, each at the bit pattern SAGE26's `set_units` forms (`R/src/core_init.c:94-106`). Their time inputs are `call.Age_galaxy_snap`, `call.halo_age` and `call.effective_steps`, recorded as `intermediate.deltaT` and `intermediate.dt`.

### Carried Intermediates of `cooling_recipe_hot`

The package splits `cooling_recipe_hot` across three modules, so it carries some of the routine's local variables between them (`C:142-200`). No SAGE26 entry point exposes those locals, so the oracle obtains them as follows, with its flags fixed:

**The transcription check.** On every fixture where `do_AGN_heating` is entered, the oracle feeds the transcribed `x` and `rcool`, with the post-cap mass, into SAGE26's own `do_AGN_heating` on a copy of the input. The return value and the five fields `do_AGN_heating` writes (`BlackHoleMass`, `HotGas`, `MetalsHotGas`, `r_heat`, `Heating`; `C:607-620`) must equal those of `cooling_recipe_hot` bit for bit, or the oracle refuses to write the fixture. Where `do_AGN_heating` is not entered, the `AGNrecipeOn 0` call must have produced exactly the state and return value of the real one. On the normal tail, `RcoolToRvir` must equal the transcribed `rcool / Rvir` narrowed to float.

**Validation of `x` and `rcool`.** A passing check does not constrain `x` or `rcool` on every path: `x` drops out when the Eddington cap (`C:557`) or the heating cap (`C:568-571`) binds, or when `BlackHoleMass` is 0, and `rcool` drops out of the suppression when `r_heat` is 0 (`C:592`). Even on a path where a value does reach the outputs, a one-ulp change of it is often absorbed by the roundings that follow, and in one direction only. So on each checked fixture the oracle reruns the check four times: with `x` replaced by its upward neighbouring double, then its downward one, and the same for `rcool`. Each rerun records whether the replacement changes a double output of `do_AGN_heating` (its return value or `Heating`) as `<name>_validated_up` or `<name>_validated_down`. The value is **validated** on that fixture only if both directions change an output (`<name>_validated` = 1, two-sided validation). The package's oracle tests assert `x` and `Rcool` only on fixtures where they are validated two-sided.

### Diagnostics and Early Returns

SAGE26's `init_galaxy` never initialises `CoolingRate` (`R/src/model_misc.c:172-198`), and the early returns leave several diagnostics as they were, so every fixture sets `tcool`, `tff`, `RcoolToRvir`, `CoolingRate`, `Cooling` and `Heating` explicitly. Unless an `.in` comment says otherwise they are negative bit patterns that no c04 routine writes (-11, -22, -33, -44, -55 and -66), and the output records them as SAGE26 leaves them:

- Every `cooling_recipe_hot` call first sets `tcool = 0` (`C:139`).
- The outer-guard failure (`C:141`) writes nothing else before the tail, which writes `CoolingRate` from a zero mass; `tff`, `RcoolToRvir` and `Cooling` keep their input values.
- The `lambda <= 0` and `rho_rcool <= 0` early returns come after `tcool` and `tff` are written (`C:145-148`) and leave `RcoolToRvir` (`C:175`), `Cooling` (`C:302`) and `CoolingRate` (`C:310`) at their input values. No fixture assumes a creation value SAGE26 does not define.

`lambda <= 0` is unreachable: every table value lies between -23.41 and -20.46 (log10 cgs, `R/src/core_cool_func.c:85-94`); `logZ` is clamped to the metallicity grid (`:142-146`) and `log10(T)` below 4.0 is raised to 4.0 (`:113-115`), so inside the table the rate is an interpolation between table values; and every table's last interval rises, so the extrapolation above 8.5 (`:118-128`) only raises it. Lambda is `pow(10.0, rate)` (`:158`) with `rate` at least about -23.41, a positive double, for every finite input. Infinite inputs are outside this argument (the conversion of an infinite `log10(T)` to the table index at `:117` is undefined in C) and are not R0 states. `rho_rcool <= 0` is reachable only by constructed inputs (a subnormal `Vvir` that overflows the float `Rvir / Vvir` to infinity, or a negative `Rvir`), and two fixtures cover it. `dt <= 0` is not a fixture case: on R0 the `Age[-1]` extension (`R/src/core_init.c:60-67`) makes `deltaT` positive at snapshot zero, and the package's `process()` skips or rejects a non-positive `dt`; the oracle refuses a fixture whose `dt` is not positive.

### Fixtures and Regenerating

Each `.in` file states in its comments what it exercises. Fixtures named `*_r0_snap<N>_*` take a real galaxy's values from the R0 reference output at snapshots 32 and 63 (end-of-snapshot values used as plausible inputs, not reconstructed call-time state). The R0 `do_AGN_heating`, `cool_gas_onto_galaxy` and interpolation fixtures take `x`, `rcool`, the masses and the table arguments from the oracle output of the R0 `cooling_recipe_hot` fixture of the same galaxy, and say so; the R0 normalisation fixtures convert the output's `Cooling` and `Heating` back to code units and multiply by the interval. The constructed edge states (a subnormal `Vvir`, a negative `Rvir`, `Vvir` of 10^5 to 10^6 km/s where the Eddington and reservoir caps bind, subnormal masses) are not R0 output but are defined exactly by SAGE26's code; each `.in` says so. `regenerate.sh` rewrites the c04 outputs together with c03's, as above.

## The c05 Group: Star Formation, Feedback, Instability, Histories and Outflow

`oracle_c05.c` covers SAGE26's disk star formation (`SFprescription 0`), its non-FIRE supernova feedback, the H I diagnostic, the disk yield, the shared star-formation and feedback commits that bursts also call, the disk instability's stellar transfer, and the driver and writer arithmetic of the per-substep SFR histories and `OutflowRate`. `S` is `R/src/model_starformation_and_feedback.c`, `D` is `R/src/model_disk_instability.c`, `B` is `R/src/core_build_model.c` and `W` is `R/src/io/save_gals_hdf5.c`.

### Flags and Parameters

Every routine that can reach the instability reads, and the oracle requires, R0's flags: `SFprescription 0`, `SupernovaRecipeOn 1`, `CGMrecipeOn 0`, `FIREmodeOn 0`, `EnhancedStarFormationOn 0`, `KarpovModeOn 0`, `SaveFullSFH 0`, `AGNrecipeOn 2` and `StarburstColdGasOn 1` (absent from R0's parameter file, so SAGE26's default, `R/src/core_read_parameter_file.c:109`). `DiskInstabilityOn` is 1 (R0); a `starformation_and_feedback` fixture may set it to 0, a labelled non-R0 value used to run star formation, feedback and the yield on unstable disks, every line of which is also on R0's path. The parameters are R0's (`R/input/millennium.par:66-89`, with `FeedbackReheatingEpsilon 2.9`) and the code constants SAGE26 derives at initialisation (`EtaSNcode` and `EnergySNcode`, `R/src/core_init.c:102-103`; `G`, `core_init.c:96`), each at SAGE26's bit pattern. `FracZleaveDisk` is 0 (R0) except in three fixtures labelled NOT R0 (`yield_frac_z_leave_positive`, `yield_frac_z_leave_satellite`, `rounding_yield_regroup_frac_z_leave`). The parameters the instability's c06 continuation reads (`BlackHoleGrowthRate`, `QuasarModeEfficiency`, `ThreshMajorMerger`, `UnitVelocity_in_cm_per_s`) are carried by every fixture that can reach it, so a perturbed recomposition that newly reaches the gas branch runs SAGE26's own code on set values.

These routines also read `BulgeSizeOn` from the fixture rather than pinning it: 0 (R0) or 3 (R1 onward, the Tonini sizes); modes 1 and 2 are not ported, and any other value is refused with an error naming `params.BulgeSizeOn`. Mode 3's size fallbacks read `Hubble_h` (`R/src/model_misc.c:249,398`), which these routines already read for every configuration (the H I diagnostic uses it), so a mode-3 c05 fixture carries `params.Hubble_h` exactly as a mode-0 one does. Every fixture before c07 whose routine reads `BulgeSizeOn` is mode 0; the c07 group adds mode-3 `check_disk_instability` fixtures (`di_s3_*`), which also record the bulge sizes ("The c07 Group"). No c03 or c04 routine reaches `get_bulge_radius` or `update_instability_bulge_radius`, the only physics readers of `BulgeSizeOn` (`R/src/model_misc.c:242`, `:395`), so c03 and c04 fixtures carry no `BulgeSizeOn`.

### Carried Values, the Composition Check and Two-Sided Validation

The package splits `starformation_and_feedback` across modules, so it carries values SAGE26 keeps in locals. The oracle obtains them from a recomposition of the wrapper in SAGE26's statement order (`compose_wrapper` in `oracle_c05.c`): the **transcribed** `sfr_croton06` (`S:160-184`), H I block (`S:1035-1046`, with `atomic_disk_radius` and `ionized_gas_fraction`, `S:130-152`), `stars = strdot * dt` and its floor (`S:1048-1051`), `compute_sn_feedback`'s non-FIRE, non-Karpov path (`S:735-799`, `S:876-889`) and disk history sampling (`S:1058-1060`); SAGE26's own `get_metallicity` and `update_from_star_formation`; the **transcribed** reheating clamp (`S:1079-1082`); `update_from_feedback`; `check_disk_instability` when `DiskInstabilityOn` is 1; and the **transcribed** yield (`S:1093-1109`). The oracle refuses a fixture unless the recomposition reproduces SAGE26's own end state in every recorded field bit for bit twice: once with SAGE26's own `update_from_feedback` and `check_disk_instability`, and once with their transcriptions (`transcribe_update_from_feedback`, `S:1153-1249` on the R0 path, and the instability transcription below). Every transcription restates SAGE26's statements with the same expression shapes and operand order and is compiled with the same flags, so contraction treats them alike; the checks confirm it on every fixture. In the reference objects clang fuses nine multiply-adds on these R0 paths: five scalar ones, which the oracle's transcriptions fuse identically and no others (checked in the disassembly with line tables): `atomicH = ColdGas * HYDROGEN_MASS_FRAC - H2gas` (`S:1036`), the yield's `MetalsColdGas += Yield * (1.0 - FracZleaveDiskVal) * stars` (`S:1097`), `MetalsColdGas -= metallicity * reheated_mass` (`S:1168`) and `MetalsHotGas += metallicity * reheated_mass` (`S:1229`) in `update_from_feedback`, and the instability's `MetalsBulgeMass += metallicity * unstable_stars` (`D:79`); and all four updates of `update_from_star_formation` (`S:1123-1126`), as two vector `fmla.2d`, one over `ColdGas` and `StellarMass` (`ColdGas - (1 - RecycleFraction) * stars` and `StellarMass + (1 - RecycleFraction) * stars`, each rounded once) and one over `MetalsColdGas` and `MetalsStellarMass` (the product `metallicity * (1 - RecycleFraction)` rounded first, then fused with `stars`). The oracle calls SAGE26's own `update_from_star_formation` and transcribes none of it. The c06 burst fixture `burst_fused_update_sf` separates the fused update from an unfused one (README "The c06 Group"). A port must round at the same points; the `rounding_*` fixtures below fail one that does not. A `starformation_and_feedback` fixture whose disk is gas-unstable after feedback is refused: its instability would run `grow_black_hole` and `collisional_starburst_recipe` (c06). Such disks are covered by the `check_disk_instability` fixtures and, with `DiskInstabilityOn 0`, by the wrapper.

Each carried value `<name>` is written as:

| Output field | Type | Meaning |
|---|---|---|
| `intermediate.<name>_absent` | `i32` | 1 if the path leaves it undefined, and then nothing else below is written for it |
| `intermediate.<name>` | `f64` | the value |
| `intermediate.<name>_checked` | `i32` | 1: the composition check that produced it passed (the oracle writes no output otherwise) |
| `intermediate.<name>_validated_up`, `_validated_down` | `i32` | 1 if replacing the value by its upward (`nextafter(v, +inf)`), respectively downward, neighbouring double changes at least one recorded float field of the end state |

The values, in statement order: `tdyn`, `cold_crit`, `strdot`, `atomicH` (after its floor), `f_ion`, `stars_pre_renorm` (`strdot * dt` after the floor), `reheated_mass_pre_renorm`, `renorm_fac`, `stars` and `reheated_mass` (after the renormalisation), `ejected_mass_pre_floor`, `ejected_mass` (after the floor), `metallicity_sf` and `metallicity_fb` (the cold-gas metallicity at each use), `reheated_mass_sf_clamped` (after `S:1079-1082`), the locals of `update_from_feedback` (`reheated_mass_fb_clamped`, `ejected_mass_capped`, `metallicity_hot`, `metals_hot_to_eject` and `metals_hot_to_eject_capped`), the instability's `diskmass`, `Mcrit`, `unstable_gas`, `unstable_stars`, `instability_metallicity` and `unstable_gas_fraction`, and the yield's `FracZleaveDiskVal` and `yield_metals_to_hot` (`metals_leaving_disk` or `all_metals`). A perturbed run uses SAGE26's own routines downstream, except the routine the value is a local of (`update_from_feedback` or `check_disk_instability`), which is replaced by its checked transcription. A neighbour on which one of SAGE26's assertions would abort (a negative reheated mass, `S:771`, `S:1158-1163`) counts as not changing the output.

Branch flags are `i32` fields `intermediate.<flag>`: `sf_vvir_nonpositive`, `sf_above_critical`, `stars_floored`, `atomicH_floored`, `f_ion_path` (0 a non-positive input, 1 `sigma0 <= 0.5`, 2 the general expression, 3 and 4 its clamp to 0 and to 1), `renorm_active`, `ejection_vvir_nonpositive`, `ejected_floored`, `reheat_clamp_sf_binds`, `reheat_clamp_fb_binds`, `ejected_cap_binds`, `metals_cap_binds`, `instability_disk_positive`, `instability_mcrit_capped`, `instability_stars_transferred`, `instability_gas_branch` and `yield_coldgas_above_threshold`; -1 means the path did not evaluate it. Where a clamp or cap binds, the `*_binds` flag (or `instability_mcrit_capped`) names it, and the recorded value after it equals the reservoir it was clamped to at that moment: `reheated_mass_sf_clamped` and `reheated_mass_fb_clamped` the forming galaxy's `ColdGas` after star formation; `ejected_mass_capped` the central's `HotGas` after the reheated gas is added and before the ejection debit; `metals_hot_to_eject_capped` the central's `MetalsHotGas` at the same point; `Mcrit` the disk mass. These are intermediate reservoir values, not the routine's output fields (the debit that follows changes them). The two-sided test perturbs the recorded post-clamp value where it is held, after the clamp, and does not clamp it again, so a binding fixture can still be validated (several are, for example `sn_ejected_capped`). A consumer keys an equality assertion off the `*_binds` flag, comparing the value with the reservoir at that point, and keys the value assertion itself off `_validated` as usual.

**Most carried values are not validated two-sided, and that is a property of SAGE26's float reservoirs.** Every field these routines write is a `float`, so a one-ulp change of a double is absorbed by the float store unless the double result lies on a float rounding midpoint, and a single store on a midpoint moves in one direction only. The `validate_*_tie` fixtures are constructed so that two stores sit on midpoints of opposite parity, which validates `stars`, `reheated_mass` and `ejected_mass` (none of them clamped or capped) two-sided; their `.in` comments give the construction. `f_ion` reaches the output only through the float `H1gas`, so its two-sided test is recorded, not required.

### The Instability

`check_disk_instability` fixtures run SAGE26's own routine for the end state, and a **transcription** of `D:54-101` (`transcribe_check_disk_instability`): the float disk-mass sums, `Mcrit` from the float `Vmax * Vmax` with SAGE26's double `3.0` (`D:35`), its cap at the disk mass, the double fractions, the stellar transfer into the float `BulgeMass`, `InstabilityBulgeMass` and `MetalsBulgeMass` with SAGE26's own `get_metallicity` of the float disk differences, SAGE26's own `update_instability_bulge_radius` (which returns at once on R0, `R/src/model_misc.c:395`), and the gas branch's `unstable_gas / ColdGas`. Where the gas branch is reached, the transcription is composed with SAGE26's own `grow_black_hole` and `collisional_starburst_recipe`, called with exactly the arguments of `D:102-108`. The oracle refuses the fixture unless the transcription, so composed where needed, reproduces SAGE26's end state bit for bit, on stable disks and disks with no cold gas as well as on gas-unstable ones. `intermediate.state_is_post_transfer` says what `galaxy[<i>].*` holds: 0, SAGE26's end state (no gas branch); 1, the transcription's state after the stellar transfer and before the c06 continuation (gas branch). On gas-unstable fixtures SAGE26's full end state is recorded under `intermediate.c06.galaxy[<i>].*`: it belongs to c06 (the black-hole growth, quasar wind and burst), is recorded for later use, and is not a c05 assertion. `intermediate.post_transfer_absent` is 0 on gas-unstable fixtures, which then carry `intermediate.post_transfer.<field>_checked`, `_validated_up`, `_validated_down` and `_validated` for `BulgeMass`, `MetalsBulgeMass` and `InstabilityBulgeMass`: the same composition rerun with that float field replaced by its neighbouring floats. `unstable_gas_fraction` and the other instability values carry the markers of the table above, from the same composition. `unstable_gas_fraction`, the value handed to c06's black-hole growth and burst, is validated in neither direction on any of the six gas-unstable fixtures: it reaches the float state only through `grow_black_hole` and `collisional_starburst_recipe`, whose float stores absorb a one-ulp change. It is checked only through the composition: the transcribed fraction, passed to SAGE26's own continuation, reproduces SAGE26's end state bit for bit.

### Driver and Writer Transcriptions

`evolve_galaxies` and the writer are not in the link, so these are **transcriptions** in `oracle_c05.c`, each labelled with its lines: the step bin `(step * STEPS) / effective_steps` capped at `STEPS - 1` and `dt = deltaT / effective_steps` (`B:513-516`); `SubstepsUsed = effective_steps` on every galaxy of the halo (`B:466-467`, sequence fixtures); the normalisation of `Cooling`, `Heating` and `OutflowRate` by galaxy zero's `1.0 / deltaT` for every galaxy with `mergeType` not above 0 (`B:590-604`, with c04's input conventions and the same Type 3 rule); the writer's averaging (`W:934-959`): ten bins summed in increasing order into float accumulators, each rate term SAGE26's left-to-right `rate * UnitMass_in_g / UnitTime_in_s * SEC_PER_YEAR / SOLAR_MASS / divisor` and each metallicity term the float `metals / gas / divisor`, skipping bins whose sampled gas is not above 0.0; and the writer's float `OutflowRate` conversion (`W:995`), for every galaxy written, merged ones included. Their outputs use the `intermediate.writer.` prefix.

### Fixtures and Regenerating

Each `.in` states in its comments what it exercises. Fixtures named `*r0_snap<N>*` take real galaxies' values from the R0 reference output at snapshots 32 and 63 (end-of-snapshot values used as plausible inputs, not reconstructed call-time state; the Age values are c03's; the histories are zero, as at substep 0 after SAGE26's first-occupied reset, unless the comment says otherwise). The R0 central fixtures with an unstable disk raise the output `ColdGas` and `MetalsColdGas` by 25%, and say so: R0's end-of-snapshot centrals sit at their Toomre threshold. Constructed edge states (subnormal or tiny reservoirs, negative metal reservoirs, `-0.0` history gas, the `validate_*_tie` inputs) are defined exactly by SAGE26's code; each `.in` says so. The rounding-point fixtures (`rounding_*`, `uff_rounding_*`, `di_rounding_*`, `avg_rounding_order`, `outflow_rounding`) are constructed so that a one-rounding difference reaches a float store: each of the five scalar fused multiply-adds above, the yield's left-to-right `Yield * (1.0 - FracZleaveDiskVal) * stars` grouping (`rounding_yield_regroup_frac_z_leave`, with a labelled non-R0 `FracZleaveDisk` 0.3, since at R0's 0 both groupings coincide), the instability's `gas_fraction * (diskmass - Mcrit)`, the writer's left-to-right unit conversions and float metallicity division order, and the normaliser's multiplication by the inverse interval. A port that fuses, splits or regroups one of them differently fails there, while on ordinary inputs the float stores hide the difference. One grouping is not pinned by any float store: the yield's escaping metals, `Yield * FracZleaveDiskVal * stars` (`S:1100`, `metals_leaving_disk`, recorded as `intermediate.yield_metals_to_hot`). Regrouped as `Yield * (FracZleaveDiskVal * stars)`, it changes only that recorded double, which no fixture validates, on `rounding_yield_regroup_frac_z_leave` and `yield_frac_z_leave_positive`, and no float store (an executed mutant). It matters only off R0: R0's `FracZleaveDisk` of 0 makes it `+0` in either grouping. Each sequence fixture has a single-call companion, `<sequence>_final_substep` (`seq_es10_final_substep`, `seq_es13_final_substep`, `seq_r0_snap32_satellite_es13_final_substep`, `seq_r0_snap63_satellite_es10_final_substep`): a `starformation_and_feedback` fixture whose input is the oracle-generated state entering the sequence's final substep. That state is obtained by chaining `oracle_c05` single calls for the earlier substeps, each call's recorded end state bit for bit being the next call's input. Every other field is as in the sequence's `.in`. A sequence output records per substep only the bin and `stars`, `reheated_mass` and `ejected_mass`, to stay within the package reader's limit of 512 fields per fixture at the time (now 2048, "Reader Limits"); the companion carries the full carried-value record for the final substep, checked and validated like every single-call fixture. Its end state equals the sequence's. `regenerate.sh` rewrites the c05 outputs together with c03's and c04's, selecting `oracle_c05` by routine.

## The c06 Group: Merger Clocks, Mergers, Black Holes, Bursts and Disruption

`oracle_c06.c` covers SAGE26's merger clock, black-hole growth and quasar wind, the collisional starburst in both modes, the merger transaction and its parts, disruption to the ICS, and the driver arithmetic around them (the per-substep merger and disruption pass, and the clock, infall and history assignment of progenitor joining), in the R0 configuration. `M` is `R/src/model_mergers.c`, `B` is `R/src/core_build_model.c`, `S` is `R/src/model_starformation_and_feedback.c` and `D` is `R/src/model_disk_instability.c`. `build.sh` compiles `oracle_c06.c` with the same flags and links it against the same twelve objects, in the same way, into `output/oracle/oracle_c06`; `regenerate.sh` runs it on every fixture whose `routine` line names a c06 routine (the `C06_ROUTINES` list), whichever module owns it. Run one by hand as `output/oracle/oracle_c06 <input> <output>`. This group changes no earlier oracle main or fixture. Of the earlier sections it changes only c05's fused-site statement (`update_from_star_formation` fuses its four updates as two vector `fmla.2d`, so c05 has nine fused multiply-adds, not five) and the count that follows from it; the c03 and c04 sections are unchanged.

### Carried Values, Check Kinds and Two-Sided Validation

The package splits these routines across modules and events, so it carries values SAGE26 keeps in locals. The oracle obtains them from **transcriptions** of the routines in `oracle_c06.c` (`transcribe_estimate_merging_time`, `transcribe_grow_black_hole`, `transcribe_quasar_mode_wind`, `transcribe_collisional_starburst_recipe`, `transcribe_update_from_feedback` (c05's, restated), `transcribe_add_galaxies_together`, `transcribe_merger_remnant_radius`, `transcribe_deal_with_galaxy_merger` and `transcribe_disrupt_satellite_to_ICS`), each statement cited to its SAGE26 line, on R0's paths only. A composition runs the selected routine's transcription with each routine it calls either SAGE26's own or its transcription. The oracle refuses a fixture unless every composition it uses reproduces SAGE26's own end state in every recorded field bit for bit (and, for the clock, SAGE26's return value): the fully transcribed one, the one with SAGE26's own sub-routines, and, for each carried value, the composition that transcribes the value's routine and the routines that call it while every other routine is SAGE26's own.

A carried value is **continuation-checked** when the routine passes the variable holding it to a SAGE26 function (the composition with SAGE26's own sub-routines then feeds the transcribed value into SAGE26's function on a copy), and **tail-checked** when it does not (the composition then runs the transcribed rest of the routine from that value to its end). Most values are validated on few fixtures, for the reason c05 gives: every field these routines write is a float, so a one-ulp change of a double is absorbed by the float stores unless a store cancels. The `*_validate_*` fixtures are built so that one does (a reservoir holding the negative of the value's contribution, or an ejection that nearly empties the hot gas), and validate each value at least once where that is possible. Seven values cannot be validated two-sided on any input, and their markers are informative only: on R0 (`BulgeSizeOn 0`) `old_disk_radius` and `new_merger_radius` never reach the state (`update_instability_bulge_radius` returns at once and `get_bulge_radius` zeroes the radii, `R/src/model_misc.c:241-246`, `:395`), and with `BulgeSizeOn 3` each reaches it only through one double-to-float store (`new_merger_radius` into `MergerBulgeRadius` on the major and spheroid-dominated minor branches, `M:307`, `:328`, discarded on the disk-dominated minor branch, `M:318-325`; `old_disk_radius` through the burst's instability-radius update into `InstabilityBulgeRadius`, `R/src/model_misc.c:422`), so they are narrowing-limited ("The c07 Group"); `central_disk_mass`, `disk_mass_post`, `disk_fraction_post` and `hot_gas_energy` reach it only through a single comparison, which a one-ulp change flips in one direction only; and `yield_metals_to_hot` reaches it only through a single float store (`MetalsHotGas += metals`, `R/src/model_misc.h:72`) that `update_from_feedback`'s metals cap has made non-negative beforehand (`S:1238-1240`), so no cancellation is possible. `FracZleaveDiskVal` is exactly 0 on R0, so it is validated only by a labelled non-R0 probe.

Branch flags are `i32` fields `intermediate.<flag>`, -1 when the path did not evaluate them: `clock_same_halo`, `clock_guard_passed`, `clock_capped`; `mass_ratio_path` (0 `mi / ma`, 1 the `ma <= 0 < mi` branch, 2 both zero, `M:243-249`) and `major_merger`; `satellite_disk_positive`, `disk_fraction_above_half` and `satellite_ics_positive`; `bh_coldgas_positive`, `bh_accretion_cap_binds` and `bh_metals_floor_binds`; `wind_ejects_cold` and `wind_ejects_hot`; `burst_gas_floored`, `burst_stars_floored`, `burst_renorm_active`, `burst_ejection_vvir_nonpositive`, `burst_ejected_floored`, `reheat_clamp_fb_binds`, `ejected_cap_binds`, `metals_cap_binds`, `burst_instability_recheck_ran`, `burst_instability_recheck_changed_state` (an observation, not a transcription: whether SAGE26's own `check_disk_instability` changed the host's reservoirs or histories or the FoF central's reservoirs) and `burst_yield_minor_branch` (the yield's `M:814` condition); `disrupt_stars_positive` and `disrupt_ics_positive`. Where a cap or clamp binds the recorded value after it equals the reservoir it was clamped to at that moment, as in c05; the two-sided test perturbs the recorded post-clamp value without clamping it again.

On R0 (`BulgeSizeOn 0`) `deal_with_galaxy_merger` computes the remnant radius (`M:293-297`) and then `get_bulge_radius` zeroes every radius on every path (`M:302-331`, `R/src/model_misc.c:241-246`): on the mode-0 fixtures `new_merger_radius` is recorded so a port can show its computation is output-inert, and is not validated. That holds for R0 only. With `BulgeSizeOn 3` (R1 onward) the remnant radius reaches `MergerBulgeRadius` on the major and spheroid-dominated minor branches, by one narrowing of the double into the float, and is discarded on the disk-dominated minor branch (`M:299-330`); the `merge_s3_*` fixtures record it, with the remnant's locals and branch flags, as narrowing-limited values ("The c07 Group"): checked through SAGE26's own `deal_with_galaxy_merger`, compared bit for bit by the package's test, never claimed as validated two-sided.

### Driver Transcriptions

`evolve_galaxies` and `join_galaxies_of_progenitors` are static in `core_build_model.c`, which the oracle's link excludes, so `merger_pass`, `join_progenitors` and `join_and_pass` are **source-reviewed transcriptions**, every statement cited to its line, and their fixtures are named `tr_*`. Where they call a SAGE26 routine (`disrupt_satellite_to_ICS`, `deal_with_galaxy_merger`, the halo helpers, `estimate_merging_time`, `get_disk_radius`, `get_bulge_radius`) the continuation is SAGE26's own; that shows nothing about the transcription itself. A mutation sweep covers them (this slice's validation record).

- `merger_pass` (`B:519-587`): for each galaxy in order, a Type 1 or 2 with `mergeType` 0 has its clock decremented by `deltaT / effective_steps` (`B:529-530`, float store); the interpolated `Mvir - deltaMvir * (1 - (step + 1) / N)` without a floor (`B:534`, a fused multiply-subtract in the reference objects) and the float `StellarMass + ColdGas` (`B:535`) gate it (`B:537`); the target is the FoF central for a Type 1 and the galaxy's own `CentralGal` for a Type 2, redirected once through the target's `CentralGal` if the target has merged (`B:539-543`); `mergeIntoID` is `call.numgals` plus the target (`B:545`); a finite clock (`B:547`) leads to `disrupt_satellite_to_ICS` while it is positive and otherwise to `deal_with_galaxy_merger` with the step bin and `dt` (`B:574-582`), at the event time `Age - (step + 0.5) * (deltaT / N)` (`B:549`, fused). Joining sets every galaxy's `CentralGal` to its subhalo's Type 0 or 1 galaxy, so a Type 1's `CentralGal` is itself and the one-hop redirect of an orphan whose Type 1 has just merged lands on that merged galaxy: SAGE26's quirk, kept (`tr_pass_redirect_consumed_target`). The diagnostic log (`B:550-572`) is not transcribed. The oracle refuses a galaxy whose clock fails `MergTime < 999.0` (`B:524-527`, where SAGE26 returns `EXIT_FAILURE`) and a layout whose `call.centralgal` is not `galaxies[0].CentralGal` or not Type 0 (`B:393-400`). `intermediate.pass.galaxy[<i>]` records, on every path, `considered` and `action` (0 none, 1 merger, 4 disruption), and `deltaT`, `currentMvir`, `galaxyBaryons`, `gate_zero_baryons`, `gate_passed`, `merger_centralgal`, `redirected`, `clock_finite`, `event_time`, `step_bin` and `dt`, each with an `_absent` marker (1, and no value, where the path does not evaluate it: everything for a galaxy the pass does not consider, everything after the gate when it fails, `event_time` for a non-finite clock, `step_bin` and `dt` for a disruption).
- `join_progenitors` (`B:210-345`, `B:358-372`): the progenitor galaxies of one descendant (sub)halo `call.halonr`, `call.ngal` of them (`galaxy[<k>]` in the input, as `halogal` holds them, in the order `B:213-214` visits them), each from progenitor halo `call.galaxy[<k>].prog`, with `call.first_occupied` (the choice of `B:181-208`, tree bookkeeping, an input) and `ngalstart` 0. ### Fixtures and Regenerating

Each `.in` states in its comments what it exercises, and whether it is **R0-reachable** or a **constructed routine-domain probe** (inputs SAGE26's routine accepts but R0's dynamics cannot produce). ### Fixtures and Regenerating

Each `.in` states what it exercises and whether it is **R1-reachable** (or, in mode 0, R0-reachable) or a **constructed routine-domain probe**. Names carry the marks: `_probe_` names a probe, `tr_` a source-reviewed transcription fixture, `r1_snap32`/`r1_snap63` a fixture whose galaxies take a real galaxy's values from the R1 reference output (`/Volumes/Internal/results/sage26-campaign/workspace/e01-reference/out/R1/model_0.hdf5`, SHA-256 `870acea288250919624ae8a4b984a4dde7106e6355cdb972cf4880ff04635ca0`) at snapshot 32 or 63: end-of-snapshot output values used as plausible call inputs, not reconstructed call-time state, with each `.in` naming the rows and what is constructed. Every public routine has an R1-derived input at both snapshots (`gbr_r1_*`, `uibr_r1_*`, `di_s3_r1_*`, `add_s3_r1_*`, `burst_s3_r1_*`, `merge_s3_r1_*`), and so does the synchronisation (`tr_sync_r1_*`). The `*_fused`, `*_rounding*` and `*_mass_rounding` inputs were found by scratch searches recorded in each `.in`'s comments and the validation record: one per fused site, the post-store recovery of `M_old` (`uibr_m_old_post_store_rounding`, where recovering it from the pre-store mass changes the stored radius), the left-to-right solar-mass conversion of both Shen fallbacks and the left-to-right `R_old_kpc`. The size routines and channels add 62 fixtures: 42 through `oracle_c07` (21 `gbr_*`, 15 `uibr_*`, 6 `tr_sync_*`) and 20 through the c05 and c06 mains (6 `di_s3_*`, 6 `add_s3_*`, 8 `burst_s3_*`).

The merger remnant radius adds 26 `merge_s3_*` fixtures through `oracle_c06`, owned by `sage26_resolve_mergers_and_disruption`: six R1-derived mergers, a major, a spheroid-dominated minor and a disk-dominated minor at each of snapshots 32 and 63 (`merge_s3_r1_snap<N>_*`); the three branches again with deliberately stale radii on both galaxies (`merge_s3_major`, `merge_s3_minor_spheroid`, `merge_s3_minor_disk_dominated`) and a minor merger whose target is disk-dominated before the addition and not after it (`merge_s3_minor_disk_morphology_flips`, where the pre-addition flag selects the branch); every branch of the remnant radius, a baryon-free satellite (`merge_s3_satellite_empty`, R1-reachable) and the probes for the rest: `M_tot <= 0` with both sums 0 and with `M_tot` exactly 0 (`merge_s3_probe_remnant_total_nonpositive`, `merge_s3_probe_total_exactly_zero`), a target sum of 0 and a negative one (`merge_s3_probe_wind_empties_target`, `merge_s3_probe_target_sum_negative`), a positive target sum with a zero radius (`merge_s3_probe_target_no_radius`) and with a negative one (`merge_s3_probe_target_radius_negative`), both radii zero (`merge_s3_probe_both_radii_zero`, `merge_s3_probe_wind_empties_satellite_no_radius`, the latter exactly at `M:179`'s boundary) or negative (`merge_s3_probe_both_radii_negative`), and `E_final < 0` and exactly 0 (`merge_s3_probe_fused_energy_fallback`, `merge_s3_probe_energy_exactly_zero`); one separating fixture per fused remnant site (above); and two inputs where evaluating a float sum of the remnant in double changes the stored radius (`merge_s3_rounding_float_sums_major`, `merge_s3_rounding_float_sums_spheroid`).
