# Mimic Modules

Full reference: `docs/DEVELOPER-GUIDE.md` (modules section). This skill covers critical facts and gotchas; the guide has full schemas and examples.

## Module Types

**Directory module** (production): `models/<model>/modules/<name>/` containing `<name>.c`, `module_info.yaml`, optional `<name>.h` and `_tests/`. This is the standard form once a module needs tests, metadata, events, or feature guards.

**Standalone module** (prototype): a single `<name>.c` directly under `models/<model>/modules/`. Valid for early prototyping; convert to a directory module when any of the above needs arise.

## module_info.yaml Schema

The primary `.c` file is **always auto-included** — never declare it. Only list additional files under `additional_files`.

```yaml
module:
  name: my_module                          # required: lowercase_with_underscores
  description: "Brief physics summary"     # recommended

  supported_processing_modes:              # required: one or more of:
    - process_by_galaxy                    #   per-galaxy (ngal=1)
    - process_full_halo                    #   array (ngal>1), required for event emitters
    - process_per_event                    #   per-event (ngal=1, ctx->active_event set)

  dependencies:
    properties: [ColdGas, StellarMass]     # validated at startup
    parameters: [MyEfficiency]             # validated at startup

  additional_files:                        # optional: extra .c/.h files beyond <name>.c
    - helper.c

  events:
    emits:                                 # process_full_halo modules only
      - name: my_event
        description: "What triggered it"
    consumes:                              # process_per_event modules only
      - producer: other_module_name
        event: my_event

  tests:
    unit: _tests/test_unit_my_module.c
    integration: _tests/test_integration_my_module.py
    scientific: []

  docs:
    physics: README.md

  compilation_requires: [HDF5]             # optional; valid values: HDF5, MPI, GSL (uppercase)
```

## C Module ABI

Functions must be named `<module_name>_init`, `<module_name>_process`, `<module_name>_cleanup` — the name prefix **must match** the `module.name` field exactly.

```c
int my_module_init(void);
int my_module_process(struct ModuleContext *ctx, struct Halo *halos, int ngal);
int my_module_cleanup(void);
```

`init()`, `process()`, and `cleanup()` return 0 on success and non-zero on failure. `process()` receives the current FoF workspace slice as `halos` plus its length `ngal`.

## Parameters

```c
#include "module_system/parameter_helpers.h"

// Standard (reference units — most parameters):
LOAD_PARAM_DOUBLE("RecycleFraction", recycle_frac);
LOAD_PARAM_INT("ReionizationOn", reionization_on);

// Dimensional parameters that need unit conversion (declared in parameter_units.yaml):
LOAD_PARAM_DOUBLE_INTERNAL("ShamMinMpeak", min_mpeak);
// or with range validation:
LOAD_AND_VALIDATE_RANGE_INCLUSIVE_INTERNAL("ShamMinMpeak", min_mpeak, 0.0, 1e15, "context");
```

`parameter_units.yaml` lives at `models/<model>/parameter_units.yaml`. Declare a parameter there with its `units` and `h_convention` to enable automatic conversion via `*_INTERNAL` macros. Parameters not listed are assumed to already be in reference units.

## Processing Modes and Workspace Access

```c
// process_by_galaxy or process_per_event:
if (ngal != 1) {
  ERROR_LOG("single-target processing expects ngal=1, got %d", ngal);
  return -1;
}
struct Halo *halo = &halos[0];
struct GalaxyData *gal = halo->galaxy;

// process_full_halo:
for (int i = 0; i < ngal; i++) {
  if (halos[i].galaxy == NULL || halos[i].Type == 3) {
    continue;
  }
  struct GalaxyData *gal = halos[i].galaxy;
}
struct Halo *central = ctx->central_galaxy;  // always valid during module execution
struct GalaxyData *central_gal = central->galaxy;
```

## Event System

```c
// Producer (process_full_halo): emit after computing the trigger condition.
// source_index and target_index are indices into the current halos[] workspace.
module_emit_event(ctx, MY_MODULE_EVENT_MY_EVENT, source_index, target_index, value0, value1);
// <MODULE_NAME>_EVENT_<EVENT_NAME> constants are generated by make generate
```

Consumers receive routed events automatically via `process_per_event` — no defensive event-code checks needed in consumer C code.

## Logging

Never use `printf`. Use macros from `src/util/error.h`:

| Macro | Visible under | Use for |
|---|---|---|
| `DEBUG_LOG(...)` | `--debug` | Function-level tracing, variable dumps |
| `VERBOSE_LOG(...)` | `--verbose` | Processing milestones, configuration info |
| `INFO_LOG(...)` | default | Important informational messages |
| `WARNING_LOG(...)` | default | Unusual but non-fatal conditions |
| `ERROR_LOG(...)` | always | Recoverable errors |
| `FATAL_ERROR(...)` | always | Unrecoverable — terminates |

## Model-Local Shared Helpers

Shared helpers under `models/<model>/shared/` require their own `module_info.yaml` for registration. See `models/sage16/shared/module_info.yaml` as the reference pattern.

## Physical Constants

Universal constants (G, c, Z_sun, etc.) come from `src/module_system/physical_constants.h`. Model-specific scientific constants belong in model-local shared headers, not redefined inline.

## After Any Module Change

```bash
make validate-modules            # check metadata first
make generate                    # regenerate if module_info.yaml changed
make                             # build
make tests-unit summary          # run unit tests
```
